# OPS-003 — Theo dõi tài liệu xóa quá hạn

Nhóm: [11 — Ca kiểm thử vận hành và sẵn sàng (OPS-001..OPS-005)](README.md) · Kế hoạch: [Master_Test_Plan.md](../../Master_Test_Plan.md)

| Mục | Nội dung |
|---|---|
| Mục tiêu | Tài liệu ở `deleting` quá `PURGE_SLA_HOURS` được đếm, ghi log cảnh báo và xuất số liệu |
| Truy vết | BR-024, US-007, T3-02 |
| Ưu tiên | Trung bình |
| Tự động hóa | `test_delete_and_purge.py::test_overdue_deleting_documents_are_counted` |

**Các bước**
1. Dừng worker; xóa một tài liệu qua giao diện.
2. Trong CSDL: `UPDATE documents SET deleted_at = now() - interval '48 hours' WHERE status = 'deleting';`
3. Khởi động worker với `MAINTENANCE_INTERVAL_S` nhỏ (ví dụ 30); xem log worker và `curl http://localhost:9100/metrics | grep documents_deleting_overdue` ngay sau khi worker chạy việc định kỳ (trước khi việc xóa hoàn tất, hoặc chặn kho tệp để việc xóa chưa xong).
4. Khôi phục kho tệp; chờ việc xóa hoàn tất; kiểm lại số liệu ở chu kỳ sau.

**Kết quả mong đợi**
- Bước 3: log `alert_documents_deleting_overdue` mức error với `count = 1`; số liệu = 1.
- Bước 4: số liệu = 0; tài liệu `deleted`, `purged_at` có giá trị.
